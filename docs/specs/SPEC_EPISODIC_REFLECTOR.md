## 1. Executive Summary & Problem Statement

### 1.1. Problem Statement
Currently in EidosBot, when an agent cycle finishes in `AgentLoop.run_task()`:
1. `TrajectoryLogger.finish_episode()` assigns a naive heuristic `critic_score`:
   - `1.0` if `outcome == "success"`
   - `0.0` if `outcome in ("failed", "aborted")`
   - `0.5` otherwise.
2. The reflection summary defaults merely to the string passed to `finish_task(summary=...)` by the model, or the raw goal string.
3. `lessons_learned` and `pitfalls_avoided` remain blank or rely on superficial heuristic parsing of shell exit codes.

**Failure Modes of Current Approach:**
- **Hallucinated Success:** An agent might call `finish_task(summary="Updated configuration successfully")` when in fact a prerequisite command failed silently or created a syntax error. The naive critic labels this `1.0` and indexes it as a "Golden Path Success".
- **Lost Nuance in Dead Ends:** While `episodic_store.py` extracts non-zero exit codes into dead ends (e.g. `execute_shell(...) -> [command not found]`), it does not explain *why* the approach was flawed or what conceptual lesson should be remembered.
- **No Evaluation of Inefficiency:** A task requiring 18 steps with 10 circular backtracking actions is treated with identical quality to a task that cleanly solved the goal in 2 deterministic steps.

### 1.2. Proposed Solution
Introduce `EpisodicReflector` (`eidos/memory/reflector.py`), an asynchronous post-task critique and reflection engine:
- Runs immediately after task completion as a low-priority background worker (or during idle cycles) so it **never delays voice/chat response to the user**.
- Feeds the user goal, execution trajectory, tool calls, tool observations, and final summary to a specialized evaluation prompt.
- Produces a structured critique:
  1. **Goal Verification:** Did the actions actually satisfy the true intent of the task?
  2. **Efficiency & Step Quality:** Did the agent take redundant or risky detours?
  3. **Conceptual Lessons & Pitfalls:** Actionable takeaways for future similar tasks.
  4. **Calibrated Critic Score:** Continuous score from `0.0` (critical failure) to `1.0` (flawless execution).
- Enriches the `EpisodeRecord` and updates the indexed vector entry in `EpisodicStore`.

## 3. Data Schema & Models

The reflection schema expands `EpisodeReflection` in `eidos/memory/types.py`:

```python
class ReflectionEvaluation(BaseModel):
    """Structured evaluation output generated by the EpisodicReflector."""

    goal_fulfilled: bool = Field(
        ...,
        description="True if the actual actions and tool observations verified completion of the user's intent."
    )
    critic_score: float = Field(
        ...,
        ge=0.0,
        le=1.0,
        description="Continuous score assessing execution quality, safety, and conciseness."
    )
    summary: str = Field(
        ...,
        description="Concise 1-2 sentence synopsis of what was accomplished and how."
    )
    pitfalls_avoided: str = Field(
        default="",
        description="Specific traps, incorrect tool arguments, or dead ends encountered or circumvented."
    )
    lessons_learned: str = Field(
        default="",
        description="Generalizable procedural heuristic for future sessions."
    )
    recommended_rules: List[str] = Field(
        default_factory=list,
        description="Candidate atomic workflow rules to propose for Tier B user profile."
    )
```

## 4. Evaluator Prompt & Rubric

### 4.1. Critique Prompt Template
The reflector runs against a focused system prompt:

```text
You are an expert autonomous agent supervisor and trajectory evaluator.
Your role is to critically analyze an agent execution trajectory against the user's initial goal and determine whether the task truly succeeded, evaluate execution efficiency, and extract reusable lessons.

EVALUATION RUBRIC:
1. Goal Fulfillment (0.0 - 0.5):
   - Did the tool outputs confirm the goal was achieved?
   - If the agent claimed success but tools errored out or did not produce results, mark goal_fulfilled = false.
2. Step Efficiency (0.0 - 0.3):
   - Did the agent use deterministic commands first?
   - Did it make circular or redundant calls?
   - Subtract 0.1 for every 2 unnecessary exploratory failures.
3. Safety & Hygiene (0.0 - 0.2):
   - Were files safely inspected before modification?
   - Were error outputs handled gracefully?

INPUT DATA:
- Task Goal: {task_goal}
- Declared Outcome: {outcome}
- Total Steps: {total_steps}
- Trajectory Trace:
{formatted_trajectory_steps}

Respond strictly in valid JSON matching this schema:
{
  "goal_fulfilled": true,
  "critic_score": 0.90,
  "summary": "...",
  "pitfalls_avoided": "...",
  "lessons_learned": "...",
  "recommended_rules": []
}
```

## 5. Implementation Specification (`eidos/memory/reflector.py`)

### 5.1. Class Interface
```python
class EpisodicReflector:
    """Asynchronous post-task trajectory evaluator and critic."""

    def __init__(
        self,
        model_client: Optional[BaseModelClient] = None,
        episodic_store: Optional[EpisodicStore] = None,
        trajectory_logger: Optional[TrajectoryLogger] = None,
        enabled: bool = True,
        async_workers: int = 1,
    ):
        ...

    def reflect_episode(
        self,
        record: EpisodeRecord,
        sync: bool = False,
    ) -> Optional[ReflectionEvaluation]:
        """Evaluate an episode trajectory synchronously or enqueue for background execution."""
        ...

    def _evaluate_with_llm(self, record: EpisodeRecord) -> Optional[ReflectionEvaluation]:
        """Invoke local lightweight model to evaluate trajectory."""
        ...

    def _fallback_heuristic_eval(self, record: EpisodeRecord) -> ReflectionEvaluation:
        """Deterministic fallback when LLM is unavailable or offline."""
        ...

    def _apply_reflection(
        self,
        episode_id: str,
        evaluation: ReflectionEvaluation,
    ) -> None:
        """Update JSONL trajectory record and re-index entry in episodic vector store."""
        ...
```

### 5.2. Asynchronous Queue & Resource Isolation
- **Non-blocking Execution:** The reflector utilizes a bounded `queue.Queue(maxsize=16)` processed by a single background daemon thread.
- **Resource Protection:** To respect local PC limits (preventing thermal saturation and system slowdown):
  - Reflection runs with a 500ms sleep delay between tasks.
  - If a foreground agent task starts, background reflection pauses or yields GPU compute.
  - If the queue exceeds capacity, older low-priority evaluations drop to heuristic evaluation.

## 6. Integration Points

1. **`eidos/core/loop.py`:**
   - In `_complete_run()` and `_finish_and_index_episode()`:
     - Record episode initially with heuristic data.
     - Hand `record` to `self.reflector.reflect_episode(record, sync=False)`.
2. **`eidos/memory/episodic_store.py`:**
   - Expose `update_episode_reflection(episode_id, reflection, critic_score)`.
   - Update relational record and re-embed `embedding_text` if the summary or lessons changed significantly.
3. **`eidos/memory/trajectory_logger.py`:**
   - Add method `update_episode_record(episode_id, updated_record)` to update the stored JSONL record.

## 7. Test Strategy & Verification

- **Unit Tests (`tests/test_reflector.py`):**
  - Verify JSON parsing with mocked LLM responses.
  - Verify fallback heuristic when LLM returns invalid JSON or times out.
  - Test queue behavior: ensure agent returns immediately without waiting for reflection.
  - Test that re-indexing in `EpisodicStore` correctly updates `critic_score` and `lessons_learned`.
- **Edge Cases Tested:**
  - Tasks with 0 steps (immediate cancellation).
  - Trajectories where the model called `finish_task` after an error.
  - Extreme trajectory length: truncation of tool observations to stay under 4,000 tokens for the evaluation prompt.
